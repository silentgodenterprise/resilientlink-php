# ResilientLink SDK Publishing — Setup Guide
# ═══════════════════════════════════════════════════════════

## HOW IT WORKS

Every time you push a version tag to any SDK repo, GitHub Actions
automatically publishes it to the right registry. You never run
publish commands manually again.

  git tag v1.0.0
  git push origin v1.0.0
  → GitHub Actions runs → package is live worldwide in ~60 seconds


## STEP 1 — Create 5 public GitHub repos

  silentgodenterprise/resilientlink-node
  silentgodenterprise/resilientlink-python
  silentgodenterprise/resilientlink-php
  silentgodenterprise/resilientlink-ruby
  silentgodenterprise/resilientlink-go


## STEP 2 — Push SDK files + workflow to each repo

  Each repo gets:
  - The SDK source files
  - .github/workflows/publish-XXX.yml  (the workflow file for that SDK)

  Example for Node:
    cd sdk-node
    git init
    git remote add origin https://github.com/silentgodenterprise/resilientlink-node.git
    mkdir -p .github/workflows
    cp publish-npm.yml .github/workflows/
    git add .
    git commit -m "Initial release"
    git push origin main


## STEP 3 — Create registry accounts + get tokens

  ┌─────────────┬──────────────────────────────┬────────────────────────────┐
  │ SDK         │ Registry                     │ Where to get token         │
  ├─────────────┼──────────────────────────────┼────────────────────────────┤
  │ Node        │ npmjs.com                    │ Account → Access Tokens    │
  │             │                              │ → Generate New Token       │
  │             │                              │ → Type: Automation         │
  ├─────────────┼──────────────────────────────┼────────────────────────────┤
  │ Python      │ pypi.org                     │ Account Settings           │
  │             │                              │ → API Tokens → Add Token   │
  │             │                              │ → Scope: Entire account    │
  ├─────────────┼──────────────────────────────┼────────────────────────────┤
  │ PHP         │ packagist.org                │ Profile → Show API Token   │
  │             │                              │ Also need: username        │
  ├─────────────┼──────────────────────────────┼────────────────────────────┤
  │ Ruby        │ rubygems.org                 │ Settings → API Keys        │
  │             │                              │ → New API Key              │
  │             │                              │ → Check: Push rubygems     │
  ├─────────────┼──────────────────────────────┼────────────────────────────┤
  │ Go          │ github.com only              │ NO TOKEN NEEDED ✓          │
  └─────────────┴──────────────────────────────┴────────────────────────────┘


## STEP 4 — Add tokens as GitHub Secrets

  For each SDK repo:
  GitHub repo → Settings → Secrets and variables → Actions → New repository secret

  resilientlink-node:
    NPM_TOKEN = (paste npm automation token)

  resilientlink-python:
    PYPI_TOKEN = (paste PyPI token — include the "pypi-" prefix)

  resilientlink-php:
    PACKAGIST_USERNAME = (your packagist username)
    PACKAGIST_TOKEN    = (paste packagist API token)

  resilientlink-ruby:
    RUBYGEMS_API_KEY = (paste rubygems API key)

  resilientlink-go:
    (nothing — Go uses the public repo directly)


## STEP 5 — PHP only: register on Packagist (one-time)

  1. Go to packagist.org → Submit
  2. Paste: https://github.com/silentgodenterprise/resilientlink-php
  3. Click Check → Confirm
  4. Go to your package page → Edit → GitHub Webhook
  5. Copy the webhook URL
  6. GitHub repo → Settings → Webhooks → Add webhook
     Paste URL, set content type: application/json, push events only
  After this, every new tag auto-syncs to Packagist.


## STEP 6 — Publish your first version

  Do this for each SDK repo:

    git tag v1.0.0
    git push origin v1.0.0

  GitHub Actions tab → watch the workflow run → green = live ✓


## STEP 7 — Update the Go module path in go.mod

  Open go/go.mod and confirm it says:

    module github.com/silentgodenterprise/resilientlink-go

  If it still says the placeholder, update it before pushing.


## RELEASING A NEW VERSION

  1. Update version number in:
     - package.json          (Node)
     - setup.py              (Python)
     - resilientlink.gemspec (Ruby)
     - resilientlink.go      (Go — sdkVersion const)
     - ResilientLink.php     (PHP — SDK_VERSION const)

  2. Commit and tag:
       git add .
       git commit -m "Release v1.0.1"
       git tag v1.0.1
       git push origin main --tags

  3. GitHub Actions publishes automatically. Done.


## VERIFY INSTALLS WORK

  npm install resilientlink
  pip install resilientlink
  composer require resilientlink/resilientlink-php
  gem install resilientlink
  go get github.com/silentgodenterprise/resilientlink-go


## SECRETS ARE SAFE

  The SDK source code contains NO secrets — only your public API URL.
  Your API key, Supabase credentials, and Flutterwave keys all live
  in your backend .env file and never touch the SDK repos.
